## 3. 効いた施策（詳細）

### 3.1 Flight Distance は「路線 ID」として振る舞う

- Flight Distance は約 3,500 種類の値が何度も繰り返し出てくる。距離ごとに乗客の構成（Class、年齢、評価の傾向）が大きく違い、**数値というより路線を表すカテゴリ**として効く [#749007] [#747742]
- 有効だった特徴量：
  - **件数**（同じ距離の行数。train + test で数える）[#747742] [#752298]
  - **fold 内のターゲットエンコーディング**：+0.00135 [#745908]、件数と合わせて +0.0017（LGBM 0.9588 → 0.9605）[#747742]。平滑化（m-estimate, m=10）の例あり [#752298]
  - **路線プロファイル**：距離ごとの他の列の平均（評価・年齢・Class 比率など）、件数、残差（その行の値 − 距離ごとの平均）。ラベル不使用。+0.00124（5/5 fold）[#747358]、+0.002 [#752304]
  - groupby 特徴量の例：`df.groupby('Flight Distance')[COL].transform('mean')`。COL は Class, Type of Travel, Customer Type, Age, Online boarding, Inflight wifi service [#749007]
- **路線プロファイルと TE は重なりが大きい**：それぞれ単独だと +0.0013 だが、プロファイルの上に TE を足しても +0.00006。ただし TE を外すと -0.0003 [#747358]
- TabPFN では「Flight Distance と FD//10 をカテゴリとして渡す」が効いた [#747823]
- **TE は必ず fold 内で作る**。全データで作るとリークで CV が水増しされる（ランダム ID が AUC 0.77 になった例）[#751221] [#749255]

### 3.2 元データは「行を足す」より「教師・参照表」として使う

- **行をそのまま足すと悪化**：-0.00005〜-0.00038 [#745098] [#748350] [#751221]（当リポジトリの exp006 でも -0.00020）
- **教師モデル**：元データだけで学習したモデルの予測（確率・logit）を、コンペの train / test の特徴量にする。+0.00059 [#745908]、+0.00038 [#748350]、+0.0002 [#752304]
  - 重要度上位に `orig_logit` / `orig_proba` が入った例 [#745555]
- **値ごとの参照表**（当リポジトリの exp007 と同じ考え方）：参照表 + 教師で +0.00048（5/5 fold、路線特徴量の上でも有効）[#747358]
- **元データへの kNN**：近い元データ行のラベル平均。この特徴量単体で AUC 約 0.95 [#749255]
- 元データとの分布差：遅延は大きく違う。Flight Distance と Age はコンペのほうが予測力が高い（単変量 AUC：FD 0.696 vs 元 0.649）[#745932]
- スタックが大きくなると、教師特徴量の効果はスタックに吸収されて消えることがある [#748350] [#749007]

### 3.3 補助タスク特徴量（expected rating）

- 各列を他の 20 列から予測するモデル（ラベル不使用）を作り、その**期待値**と**残差（実際 − 期待）**を特徴量にする [#747358] [#751334]
- LightGBM で +0.00014（5/5 fold）、期待値だけ残すとさらに良い [#747358]。+0.00014 [#745908]
- 一方で LightGBM では -0.00012 だが RealMLP では +0.00023 という報告もある [#752304]。モデルによって効き方が違う

### 3.4 評価項目の 0（該当なし）

- 0 は「該当なし」。wifi 0 の満足率 88.7%、1 は 39.1% [#750393] [#744809]（当リポジトリの EDA と一致）
- **0 はペアで出る**：wifi = 0 の行の 82.5% は Ease of Online booking も 0。この**両方 0 のときの満足率は 94.9%**、wifi だけ 0 だと 63.6% [#750393]
- 木モデルは自力で分けられる。効くのは**線形モデルや行ごとの平均を作るとき**（0 を除いて平均する）[#750393]。当リポジトリの exp002（0 の特徴量で改善なし）と整合

### 3.5 カテゴリの交差（CatBoost 向け）

- 13 個の評価 × {Class, Type of Travel, Customer Type} の 39 列をカテゴリとして足す。CatBoost で +0.00034（3,000 iter）/ +0.00028（6,000 iter）、5/5 fold [#745892]
- 路線特徴量や教師特徴量を持つ CatBoost の上でも +0.00013、10分割で単体最良の 0.96137 [#745892 コメント]
- 前提の設定：評価 13 列をカテゴリ、数値 4 列は数値のまま＋カテゴリのコピーも追加
- 評価 × 評価の交差は不安定（3/5 fold）[#745892]
- **LightGBM では悪化**（-0.00048、0/5 fold）[#747358]

### 3.6 分割数とモデルの多様性

- **10分割**：各モデルで +0.00009〜+0.00018 [#745908]、CatBoost +0.00007（5/5 fold）[#746148]。学習データ量の効果で、学習曲線は「データ 2 倍で +0.0006」とまだ伸びている [#745932]
- **違う種類のモデル**が効く：RealMLP を足したスタックで OOF +0.0009 / LB +0.0013。GBDT を 6 種類足しても合計 +0.0006 程度 [#749255]
- RealMLP の要点：数値列をカテゴリとしても入れる、件数エンコーディング、`plr_sigma` を大きく（32）。エポック数は 6〜20 程度（128 エポックは失敗）[#749010] [#751221]
- Tabular Foundation Models（TabPFN 3.5 など）は単体で 0.9611 と強いが、A100 クラスの GPU で数時間かかる [#746363] [#749010]。当リポジトリの環境（CPU）では現実的でない
- 同じ特徴量の GBDT を増やしても、スタックではほぼ伸びない（飽和）[#746148] [#752304]

### 3.7 スタッキング

- **ロジット空間のロジスティック回帰**（L2、C=0.003 など小さめ）が、凝ったメタモデルより良い [#745908] [#746148] [#750479]
- **ネスト CV で評価**する。700k 行・16 モデル程度なら OOF での過学習はほぼない（約 0.000001）。120 モデルだと 0.00005 程度 [#746148]
- 相関 1.000000 の重複列に注意（公開 OOF の 24/40 が重複だった例）[#746148]
- スタックの OOF 残差から特徴量を作るのはリーク（CV だけ +0.00027 上がる）[#747982]

## 5. CV と LB・最終提出の選び方

- **Public LB は test の 20%（約 6 万行）**、Private は 80% [#747982]
- **CV と LB は連動する**：40 提出で相関 0.98。LB は OOF より系統的に低い（ブレンド・スタック 約 -0.0003、単体 NN 約 -0.0001）[#749255]。当リポジトリでも exp001 -0.0004、exp005 -0.0006、exp007 -0.0004
- **Public LB のノイズ**：2 つの提出の差の標準偏差 ≈ 0.0012 × √(1 − ρ)（ρ は 2 つの test 予測の順位相関）[#750480]
  - ρ = 0.999 → 約 0.00004、ρ = 0.99 → 約 0.00012
  - この式は 20〜45% 小さめに出ることがある。OOF があるなら paired DeLong のほうが正確 [#750480 コメント]
  - Public の差が 1 sd 未満だと Private で逆転する確率はほぼ 5 分 5 分、2 sd でも約 7%。3 sd 以上でようやく安全（<1%）[#750480 コメント]
- **CV の差は信頼しやすい**：700k 行なので、同じ 2 モデルの差のノイズは Public の約 0.29 倍。CV +1e-5 でも LB が上がることが多い [#750480]
- 最終提出 2 つ [#750963] [#749621] [#749255]：
  1. CV（ネスト CV）が最も高いもの
  2. 傾向の違うもの（別の特徴量セット・モデル種類）。**2 つの順位相関を確認し、0.999 以上なら実質同じ**
  - Public の上位 2 つを選ぶと、Private の最良を逃したチームが過去 5 回で 7〜17% [#749621]
  - Public LB を見ながら重みを決めたブレンドは、正直な評価値がないので避ける

## 6. データについての事実（EDA の補足）

- train と test の敵対的検証の AUC は 0.500。分布の差はない [#745098]
- train / test / 元データ間で完全一致する行はほぼない（元データと train 17 行、test 4 行）[#745932]（当リポジトリの EDA と一致）
- 単変量 AUC：Online boarding 0.840〜0.854 が最高、Gender 0.506 が最低 [#745932] [#745106]
- 1 列ずつ外したときの低下：wifi -0.0040 が最大、Customer Type -0.0011、Type of Travel -0.0008 [#745098]
- 遅延 2 列は単独ではほぼ無情報（単変量 AUC 0.5 ± 0.02）。91% が遅延 0 [#745932]
- 評価 13 列をすべて外すと AUC -0.086、遅延を外しても -0.0003 [#745106]
